# 问题修复方案：历史记录、对话续接、对话式兜底（三项）

> **用途**：本文档可独立阅读，供任何 AI / 开发者按任务清单完成修复，无需回溯历史对话。  
> **基线**：分支 `backend-main`，提交 `241da54`（2026-10-16）。开工先执行 `git log --oneline -1` 核对；若基线已前进，请以实际代码为准重新核对文中行号。

## 0. 问题清单与优先级

| # | 现象（用户实测反馈）                        | 影响                                 | 优先级    | 预估   |
| - | --------------------------------- | ---------------------------------- | ------ | ---- |
| 1 | 查看「最近记录」时，页面把该历史问题**再发给 AI 回答一次** | 每次查看都烧模型额度、等 3~7 秒、结果可能与上次不同       | **P0** | 0.5h |
| 2 | 在「最近记录」里继续聊天，**开的是新会话**，不是延续旧对话   | 历史上下文全丢；追问（如「那费用呢」）会被判 unsupported | **P1** | 1 天  |
| 3 | 非事项问题（如「你好？」）一律机械回复「暂不支持」         | 没有对话感，体验僵硬                         | **P1** | 2h   |

三个问题共用同一块地基：**后端是「单轮问题」建模，不是「对话」建模**（问题 1 也因此没有历史内容可展示）。

## 1. 问题一：查看最近记录 = 重新提问

### 1.1 复现

1. 在问答页问一句「学生证丢了怎么补办？」，得到回答；
2. 打开「最近记录」，点击该条记录（或回首页点「最近记录」里的同一行）；
3. 观察：跳到问答页后**立即又发出一次请求**，回答重新生成（后端日志/耗时可见）。

### 1.2 根因（代码级）

- **数据层没有历史内容可展示**：`backend/app/models/conversation.py:20-48` 的 `conversations` 是「一行 = 一个问题」——`question` 为单数字段，只有 `result_status` / `last_intent` / 起止时间，**AI 的回答从未落库**（`backend/app/services/chat_service.py:135-148` 的 `_history()` 注释亦印证）。
- **前端把「查看」实现成「重问」**：
  - `frontend/src/views/HomeView.vue:241`（最近记录行）→ `goChat(item.question)` → 跳 `/chat?q=<问题>`；
  - `frontend/src/views/HistoryView.vue:60`（「继续咨询」）→ `:to="{ name: 'chat', query: { q: item.question } }"`；
  - `frontend/src/views/ChatView.vue:43,166-167` → 进入即 `if (initialQuestion) void send(initialQuestion)`，**自动发送**。
- 结果：任何「看一眼历史」的动作都等价于重新提问。

### 1.3 目标行为

| 入口                   | 行为                                |
| -------------------- | --------------------------------- |
| 记录页 / 首页最近记录的**主点击** | **查看**：只展示该条记录，不发送请求              |
| 记录页「**重新提问**」按钮      | 带 `?q=` 进入并自动发送（文案明确告知会再次生成回答）    |
| 问答页 `?id=<会话id>`     | 查看 / 续接（依赖问题二改造；未完成前可降级为「展示该条摘要」） |

### 1.4 实施任务（短期方案，不动契约不动数据模型）

| #   | 文件                                      | 改动                                                                                              |
| --- | --------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 1.1 | `frontend/src/views/ChatView.vue`       | 区分入口：`?q=` 才自动发送；新增 `?id=` 分支——不发送，仅在消息列表顶部渲染一条「历史记录卡」（问题、结果状态标签、时间）。`conversationId` 仍为 `null` |
| 1.2 | `frontend/src/views/HomeView.vue:241`   | 最近记录行 `goChat(item.question)` → `router.push({ name:'chat', query:{ id: item.id } })`           |
| 1.3 | `frontend/src/views/HistoryView.vue:60` | 列表项主点击改为查看（`?id=`）；按钮文案「继续咨询」→「**重新提问**」，仍带 `?q=`                                               |
| 1.4 | `frontend/src/views/HistoryView.vue`    | 可选：在按钮上加 `title`/提示「将再次生成回答」                                                                    |

### 1.5 验收

- 点历史记录 → 问答页**不发请求**（Network 无 `/api/chat/messages`），仅展示该条；
- 点「重新提问」→ 才自动发送并生成新回答；
- 首页最近记录同上。

## 2. 问题二：继续聊天开新会话（单轮建模 → 对话建模）

### 2.1 复现

1. 问「转专业需要什么条件？」→ 得到回答；
2. 去「最近记录」点该条「继续咨询」→ 跳到问答页；
3. 输入「那费用呢？」→ 后端返回 `unsupported`（或开了一条全新会话，`conversation_id` 与之前不同）。

### 2.2 根因（代码级）

1. **无消息表**：`conversations`（`models/conversation.py:20-48`）只存单轮问题；没有 `conversation_messages`。
2. **上下文只有「上一轮摘要」**：`chat_service.py:135-148` 的 `_history()` 只拼「上一轮问题 / 事项 / 状态」，**不含 AI 的回答内容**；`_build_user_prompt()`（`:214`）也没有对话历史段。
3. **前端入口丢会话**：从记录页进来走 `?q=`，`ChatView.vue:37` 的 `conversationId` 初始为 `null` → 请求带 `conversation_id: null` → `chat_service.py:112` 判定为**新建会话**。
4. **多轮仅靠意图继承兜底**：`_run_pipeline()`（`:161-211`）只在上一轮是 `need_clarification` 时沿用事项；用户自由追问没有上下文支撑。

### 2.3 目标行为

- 历史可查：`GET /api/conversations/{id}/messages` 返回该会话全部问答；
- 历史可续：从记录页「继续咨询」进入 → 加载历史消息 → 后续轮次沿用同一 `conversation_id`；
- 上下文可用：生成提示词注入最近 N 轮对话历史（用户问题 + AI 回答摘要）。

### 2.4 数据模型（迁移 `0005`）

表 `conversation_messages`：

| 字段                | 类型                                                    | 说明                                                       |
| ----------------- | ----------------------------------------------------- | -------------------------------------------------------- |
| `id`              | String(36)                                            | 主键 uuid4                                                 |
| `conversation_id` | String(36) FK → `conversations.id`，`ondelete=CASCADE` | 所属会话                                                     |
| `role`            | String(16)                                            | `question` / `assistant`                                 |
| `content`         | Text                                                  | question 轮=用户原文；assistant 轮=回复文本（answered 时可为卡片 summary） |
| `status`          | String(24)                                            | 该轮 `AnswerStatus`                                        |
| `answer_json`     | Text                                                  | assistant 轮的结构化卡片 JSON；非 answered 为 `NULL`               |
| `sources_json`    | Text                                                  | assistant 轮的来源快照 JSON（**仍由 DB 映射生成，不采信模型输出**）            |
| `created_at`      | DateTime(tz)                                          | 入库时间                                                     |

索引：`(conversation_id, created_at)`；外键级联删除与既有迁移风格一致（参考 `alembic/versions/0002_add_conversation_session_token.py`）。  
**downgrade**：`DROP TABLE conversation_messages`。

### 2.7 边界与风险

- **消息量**：`list_messages` 默认只返回最近 200 条（或按 N 轮窗口），避免一次拉全量；
- **归属校验**：GET 与续写都必须校验 `conversation.session_token`，复用 `chat_service._resolve_conversation` 的规则（`chat_service.py:126-131`）；
- **空会话**：历史为空时前端展示「暂无对话内容」而非空白；
- **迁移顺序**：容器启动时 `alembic upgrade head` 会自动升级到 `0005`，无需人工干预（见 `backend/docs/deploy.md` §3）。

## 3. 问题三：非事项问题机械回复「暂不支持」

### 3.1 复现

在问答页输入「你好？」「在吗？」「谢谢你」→ 一律返回 `unsupported`，前端显示固定提示卡  
「这个问题暂时不在服务范围内」。用户期望：能自然对话；若与事项相关但表述不清，应反问确认（「你是在问……吗？」）。

### 3.2 根因（代码级）

- 意图识别是**纯规则**：`backend/app/services/intent.py:51-76`——关键词表未命中即 `IntentResult("unsupported", …)`（`:63`）；
- 编排层**在调用模型之前**就短路：`chat_service.py:168-171` 的 `intent_result.kind == "unsupported"` 分支直接返回 `unsupported`，没有兜底对话能力；
- 前端 `ChatView.vue` 对 `unsupported` 渲染为 `StateNotice`（固定文案 + 「看看支持事项」按钮），不是对话气泡。

### 3.3 目标行为（分类规则）

| 输入                            | 期望状态                                                 | 说明        |
| ----------------------------- | ---------------------------------------------------- | --------- |
| 问候 / 闲聊（你好、在吗、谢谢、再见）          | `smalltalk`，**规则直答**，不调模型                            | 零延迟零成本    |
| 校园事务相关但表述不清（如「我想办点事」「那个证怎么办」） | `smalltalk` + `text` 引导语（例：「你是在问学生证补办吗？我可以帮你查办理流程。」） | 模型判定 + 引导 |
| 明确库外（食堂几点开门、怎么选课）             | `unsupported`（保持现状）                                  | 不编造       |
| 命中事项                          | 现有六态不变                                               | —         |

约束：`smalltalk` **不得输出政策、时间、地点、电话**；不得给办理流程。只做寒暄与引导。

### 3.4 契约变更（`docs/api.md` v1.3 §4.7 已规划）

- `AnswerStatus` 增加 `SMALLTALK = "smalltalk"`；`conversations.result_status` 的 CheckConstraint（`models/conversation.py:23-27`）同步加入该取值；
- `ChatMessageResponse` 增加可选字段 `text: str | null`（纯文本对话内容）；
- `smalltalk` 响应：`answer=null`、`sources=[]`、`need_clarification=false`、`text` 非空。

## 8. 红线（不要动）

- `docs/api.md` 是契约权威：**先改契约再改代码**，禁止先实现后补文档；
- `sources` 一律由数据库映射生成，**不采信模型输出**（契约 §1.2）；
- 只有「已核验 + 有效期内 + 有正文」的来源才能产出 `answered`（契约 §4.3）；
- `smalltalk` 不得输出政策、时间、地点、电话、办理流程；
- 禁止执行 `git push`（由仓库负责人自行推送）；提交信息用中文、一个提交可含多个 `-m` 分段。
